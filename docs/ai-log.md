### Помилка 1: хибні повідомлення в `check.js`
**Що сталося.** Перший запуск `node .github/agent-tools/check.js` на гілці з
самим агентом (проєкту ще немає) очікувано дав `FAIL` для групи `project`, але
два повідомлення були неправильними:
- `ci.yml contains no secrets -> secret reference found` — хоча `ci.yml` просто
  відсутній (умова `exists(wf) && !regex` давала `false` і без секретів);
- падіння складання виводило весь стек Node.js (12 рядків з абсолютними шляхами).

**Рішення.** `read()` тепер кидає `"<файл> not found"`; перевірку секретів
переписано як `!regex.test(read(wf)) || 'secret reference found'`; для
`build` спочатку перевіряється наявність `scripts/build.js`, а з stderr
береться лише рядок з `Error`. Повторний запуск: `22 passed, 16 failed`,
усі причини коректні (`scripts/build.js not found`, `js-yaml not installed`).

**Висновок.** Перевірки теж треба перевіряти: хибний `FAIL` з неправильною
причиною так само шкідливий, як хибний `PASS`, бо веде до неправильного «виправлення».

### Помилка 2: некоректна команда перевірки в `/git-init`
**Що сталося.** На кроці 1/5 перевірка з `git-init.prompt.md`
`git check-ignore -q build/ node_modules/ coverage/ .env` завершилась
`fatal: --quiet is only valid with a single pathname` — інструкцію агента
згенеровано з помилкою (прапорець `-q` допускає лише один шлях).

**Рішення.** Виправлено саму інструкцію агента (у гілці `develop`), а не
результат: `git check-ignore -v build/ node_modules/ coverage/ .env` — друкує
правило `.gitignore` для кожного шляху (очікується 4 рядки). Після виправлення
`develop` злито у `feature/hello-world-js`, крок 1/5 повторено — `PASS`.
